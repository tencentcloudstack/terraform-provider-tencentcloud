## ADDED Requirements

### Requirement: Datasource zones schema includes work_mode_infos
The `tencentcloud_teo_zones` datasource SHALL define a `work_mode_infos` field within the `zones` nested schema. The field SHALL be of type `TypeList`, `Computed: true`, with each element being a `Resource` schema containing:
- `config_group_type` (TypeString, Computed): 配置组类型，取值 `l7_acceleration`（七层加速配置组）、`edge_functions`（边缘函数配置组）、`web_security`（Web 防护配置组）。
- `work_mode` (TypeString, Computed): 工作模式，取值 `immediate_effect`（即时生效模式）、`version_control`（版本管理模式）。

#### Scenario: work_mode_infos field present in zones schema
- **WHEN** the `tencentcloud_teo_zones` datasource schema is defined
- **THEN** the `zones` nested resource schema SHALL include a `work_mode_infos` field of type TypeList and Computed, whose element resource schema contains `config_group_type` and `work_mode` fields both of type TypeString and Computed

#### Scenario: work_mode_infos field descriptions document valid values
- **WHEN** the `work_mode_infos` schema fields are defined
- **THEN** the `config_group_type` Description SHALL list valid values `l7_acceleration`, `edge_functions`, `web_security`, and the `work_mode` Description SHALL list valid values `immediate_effect`, `version_control`

### Requirement: Read function flattens WorkModeInfos into work_mode_infos
The datasource Read function SHALL flatten the `WorkModeInfos` field (`[]*teov20220901.ConfigGroupWorkModeInfo`) of each `Zone` from the `DescribeZones` API response into the `work_mode_infos` list within the corresponding `zones` map entry. The Read function SHALL check `zones.WorkModeInfos != nil` before iterating, and for each `ConfigGroupWorkModeInfo` element SHALL check `ConfigGroupType != nil` and `WorkMode != nil` before setting the corresponding map keys, consistent with the existing field flattening pattern.

#### Scenario: WorkModeInfos with multiple config groups
- **WHEN** the API returns a `Zone` whose `WorkModeInfos` contains multiple `ConfigGroupWorkModeInfo` elements (e.g. one for `l7_acceleration` with `immediate_effect` and one for `web_security` with `version_control`)
- **THEN** the Read function SHALL flatten all elements into the `work_mode_infos` list, each with `config_group_type` and `work_mode` populated according to the API response

#### Scenario: WorkModeInfos is nil
- **WHEN** the API returns a `Zone` whose `WorkModeInfos` is nil
- **THEN** the Read function SHALL NOT set the `work_mode_infos` key in the zones map entry (consistent with existing nil-field handling), and other zone fields SHALL still be populated normally

#### Scenario: ConfigGroupType or WorkMode is nil within an element
- **WHEN** the API returns a `ConfigGroupWorkModeInfo` element where `ConfigGroupType` is nil but `WorkMode` is non-nil
- **THEN** the Read function SHALL omit the `config_group_type` key from that element's map while still setting `work_mode`

### Requirement: Unit tests cover work_mode_infos flattening
Unit tests SHALL be added to `data_source_tc_teo_zones_test.go` using gomonkey to mock the cloud API call (the `DescribeTeoZonesByFilter` service method or its underlying API), constructing a `[]*teov20220901.Zone` response that includes `WorkModeInfos` data, and verifying that the `work_mode_infos` output field is correctly populated.

#### Scenario: Successful read with WorkModeInfos populated
- **WHEN** the Read function is called and the mocked API returns a `Zone` with `WorkModeInfos` containing two elements (`l7_acceleration`/`immediate_effect` and `web_security`/`version_control`)
- **THEN** the test SHALL verify that the `zones` output contains a `work_mode_infos` list with two entries whose `config_group_type` and `work_mode` values match the mocked response

#### Scenario: Successful read with WorkModeInfos nil
- **WHEN** the Read function is called and the mocked API returns a `Zone` with `WorkModeInfos` set to nil
- **THEN** the test SHALL verify that the `work_mode_infos` key is absent (or empty) in the zones output without error

### Requirement: Datasource documentation updated
The `data_source_tc_teo_zones.md` file SHALL be updated to document the new `work_mode_infos` output field. The documentation SHALL include a description mentioning TEO, an Example Usage section, and reference the `work_mode_infos` nested output fields `config_group_type` and `work_mode` with their valid values. The Argument Reference and Attribute Reference sections SHALL NOT be manually added (auto-generated by tooling).

#### Scenario: Documentation includes work_mode_infos
- **WHEN** the datasource documentation is updated
- **THEN** the `.md` file SHALL exist with a one-line description mentioning TEO, an Example Usage section, and the `work_mode_infos` output field documented with `config_group_type` and `work_mode` sub-fields
