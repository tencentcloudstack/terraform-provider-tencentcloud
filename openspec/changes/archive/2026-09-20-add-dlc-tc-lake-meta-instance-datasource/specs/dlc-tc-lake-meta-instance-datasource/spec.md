## ADDED Requirements

### Requirement: Data Source Schema Definition
The data source SHALL expose a computed `status` field for the TCLake activation status, and an optional `result_output_file` field for saving results.

#### Scenario: Schema with computed status field
- **WHEN** defining the data source schema
- **THEN** `status` field SHALL be defined as TypeString, Computed, with description describing the activation status enum value (e.g. `Running`)
- **AND** `result_output_file` field SHALL be TypeString, Optional, with description "Used to save results."

### Requirement: Service Layer Integration
The data source SHALL call the DLC `DescribeTCLakeMetaInstance` API via a service layer method to query the TCLake activation status.

#### Scenario: Service layer method call
- **WHEN** reading the data source
- **THEN** the system SHALL call `DlcService.DescribeDlcTCLakeMetaInstance(ctx)` which invokes `DescribeTCLakeMetaInstanceWithContext`
- **AND** the API request SHALL have no input parameters (the interface has no request fields)
- **AND** use `ratelimit.Check(request.GetAction())` before the API call
- **AND** log API request and response bodies at DEBUG level on success
- **AND** log error with logId, action, request body, and reason on failure

#### Scenario: Null pointer protection in service layer
- **WHEN** the API response is returned
- **THEN** the service layer SHALL check `response == nil || response.Response == nil || response.Response.Status == nil`
- **AND** return nil status without error when any of these is nil

### Requirement: Read Method with Retry Logic
The data source Read method SHALL use retry logic and protect against empty responses to avoid clearing Terraform state.

#### Scenario: Read with retry and empty response protection
- **WHEN** reading the data source
- **THEN** the system SHALL wrap the service call in `resource.Retry(tccommon.ReadRetryTimeout, ...)`
- **AND** errors from the service call SHALL be wrapped with `tccommon.RetryError(e)`
- **AND** when the service returns a nil status, the system SHALL return `resource.NonRetryableError` with a message containing "dlc tc_lake_meta_instance read empty, skip SetId"
- **AND** SHALL NOT call `d.SetId("")` inside the retry block

#### Scenario: Set computed fields after successful read
- **WHEN** the service returns a non-nil status
- **THEN** `status` SHALL be set via `d.Set("status", status)` after checking non-nil
- **AND** `d.SetId("tc_lake_meta_instance")` SHALL be called with a fixed string identifier
- **AND** defer functions SHALL include `tccommon.LogElapsed` and `tccommon.InconsistentCheck`

#### Scenario: Optional result file output
- **WHEN** `result_output_file` parameter is provided and non-empty
- **THEN** the system SHALL write the status to the specified file path using `tccommon.WriteToFile`
- **AND** return error if file write fails

### Requirement: Provider Registration
The data source SHALL be registered in the Provider's DataSourcesMap.

#### Scenario: Register data source
- **WHEN** initializing the Provider
- **THEN** `tencentcloud_dlc_tc_lake_meta_instance` SHALL be mapped to `dlc.DataSourceTencentCloudDlcTCLakeMetaInstance()`
- **AND** the resource name SHALL be appended to `tencentcloud/provider.md` in the DLC Data Source list

### Requirement: Documentation
The data source SHALL include a documentation file following Terraform conventions.

#### Scenario: Documentation file content
- **WHEN** creating the documentation file `data_source_tc_dlc_tc_lake_meta_instance.md`
- **THEN** the file SHALL start with a one-sentence description that includes the DLC cloud product name and the "Use this data source to query ..." prefix
- **AND** include an Example Usage section in HCL format
- **AND** SHALL NOT include Argument Reference or Attribute Reference sections (auto-generated by tools)

### Requirement: Unit Testing with Mock
The data source SHALL have unit tests using mock (gomonkey) to mock the cloud API, testing only business logic without calling real cloud APIs.

#### Scenario: Mock-based unit test
- **WHEN** creating the test file `data_source_tc_dlc_tc_lake_meta_instance_test.go`
- **THEN** the test SHALL use gomonkey to mock the cloud API methods
- **AND** SHALL NOT use the Terraform test suite
- **AND** SHALL verify the business logic of the Read method
- **AND** the generated code SHALL be compilable and executable in the current environment
