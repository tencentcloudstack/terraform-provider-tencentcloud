## Context

TEO (EdgeOne) exposes a `CreatePlanForZone` API in the vendored SDK `teo/v20220901` (verified present — no SDK changes required):

- `CreatePlanForZone(request)` — purchases a plan for a zone that has not yet bound a plan. Request inputs: `ZoneId *string`, `PlanType *string`. Response outputs: `ResourceNames []*string`, `DealNames []*string`, `RequestId *string`.
- The API is synchronous; no async task/polling is needed.

This change is implemented as a **terraform-plugin-framework Action** (`action.Action`), not an SDKv2 operation resource. It reuses the existing `TeoPlanForZone` service-layer helper which calls `me.client.UseTeoV20220901Client().CreatePlanForZone(request)`.

## Goals / Non-Goals

**Goals:**
- Trigger plan purchase for a zone via `CreatePlanForZone` as a one-time side-effect.
- Register the Action through the framework provider's `Actions` factories in `tencentcloud/framework/registry.go`.
- Ship the per-type markdown doc (`action_tc_teo_plan_for_zone.md`), unit tests, and the `provider.md` Action section entry (website docs are generated by `make doc`).

**Non-Goals:**
- No revert/cancel of a purchased plan; Actions produce side-effects only and cannot revert state.
- No Read API to query purchase status; framework Actions have no Read lifecycle.
- No output attributes: framework Actions cannot surface output values to a caller (the `InvokeResponse` only carries diagnostics). The API's `ResourceNames` and `DealNames` are logged for diagnostics but not returned to the user.

## Decisions

### Implementation model: framework Action
- Reverted the earlier SDKv2 `RESOURCE_KIND_OPERATION` resource (`resource_tc_teo_plan_for_zone_operation.go`).
- New file: `tencentcloud/services/teo/action_tc_teo_plan_for_zone.go` implementing `action.Action` + `action.ActionWithConfigure`.
- The Action type name is `tencentcloud_teo_plan_for_zone` (set in `Metadata`), registered via `teo.NewTeoPlanForZoneAction` in `framework/registry.go` `actionFactories`.
- `Configure` receives `*sharedmeta.ProviderMeta` (set as `ActionData` by `framework.Provider.Configure`) and constructs `NewTeoService(meta.Client)`, mirroring SSM ephemeral/resource Configure.
- `Invoke` reads `zone_id`/`plan_type` from the request Config, validates they are non-empty, then calls `a.client.TeoPlanForZone(zoneId, planType)`. On error or empty response it adds an error diagnostic. The `ResourceNames`/`DealNames` are logged but not returned.

### Schema (framework action schema)
- Required:
  - `zone_id` (StringAttribute): Zone ID.
  - `plan_type` (StringAttribute): Plan type to purchase. Valid values: `sta`, `sta_with_bot`, `sta_cm`, `sta_cm_with_bot`, `sta_global`, `sta_global_with_bot`, `ent`, `ent_with_bot`, `ent_cm`, `ent_cm_with_bot`, `ent_global`, `ent_global_with_bot`.
- No output attributes (framework actions cannot be Computed and have no result-set mechanism).

### Provider registration
- Removed `tencentcloud_teo_plan_for_zone` from the SDKv2 `ResourcesMap` in `tencentcloud/provider.go`.
- Removed the SDKv2 `tencentcloud_teo_plan_for_zone` entry from the Resource section of `tencentcloud/provider.md`.
- Added `tencentcloud_teo_plan_for_zone` under a new `Action` sub-section in the TEO product block of `tencentcloud/provider.md` (consumed by `gendoc` to render `website/docs/a/` and the sidebar).
- Registered `teo.NewTeoPlanForZoneAction` in `tencentcloud/framework/registry.go` `actionFactories`.

### Service-layer method
- Reuses the existing `TeoPlanForZone(zoneId, planType string) (resourceNames, dealNames []*string, errRet error)` in `service_tencentcloud_teo.go`. No retry wrapper is added in the Action; the service helper surfaces SDK errors, and the Action converts them into diagnostics.

### Documentation file naming
- Per `gendoc/framework.go`, the per-type markdown for an Action must be `action_tc_[<product>_]<resource>.md`. The file is `tencentcloud/services/teo/action_tc_teo_plan_for_zone.md` (renamed from `resource_tc_teo_plan_for_zone.md`).

## Risks / Trade-offs

- [Actions produce side-effects only] → The API's `ResourceNames`/`DealNames` are not surfaced to the user; they are logged for diagnostics. Users who need the deal names must inspect logs or use the console.
- [Plan purchase is irreversible and billing-impacting] → Mitigation: document clearly that the action performs a real purchase and cannot be cancelled.
- [Re-running the action on a zone that already has a plan] → Mitigation: rely on the API's own behavior; `CreatePlanForZone` will surface an error which the Action reports as a diagnostic.
