## Why

The `dbdc` (DB Custom) service exposes placement-group (置放群组) APIs —
`CreateDBCustomDisasterRecoverGroup`, `DescribeDBCustomDisasterRecoverGroups`,
`ModifyDBCustomDisasterRecoverGroupAttribute` and
`DeleteDBCustomDisasterRecoverGroups` — but the Terraform provider has no resource
to manage a placement group's full lifecycle. Users currently cannot declare the
creation, attribute modification, or deletion of a DB Custom placement group
through Terraform, which forces imperative API calls or console clicks alongside
their IaC workflow.

## What Changes

- Add a new `RESOURCE_KIND_GENERAL` resource
  `tencentcloud_dbdc_db_custom_disaster_recover_group` that manages a DB Custom
  placement group via full CRUD.
  - **Create** → `CreateDBCustomDisasterRecoverGroup` (async via returned
    `Status`; poll `DescribeDBCustomDisasterRecoverGroups` until the group is
    `Available`).
  - **Read** → `DescribeDBCustomDisasterRecoverGroups` filtered by
    `DisasterRecoverGroupIds`.
  - **Update** → `ModifyDBCustomDisasterRecoverGroupAttribute` for mutable
    fields (`name`, `affinity`); other top-level fields are immutable
    (`ForceNew` or rejected in `immutableArgs`).
  - **Delete** → `DeleteDBCustomDisasterRecoverGroups` (async via `TaskId`;
    poll `DescribeDBCustomTaskStatus` until `Succeeded`).
- Register the resource in `provider.go` ResourcesMap and `provider.md`.
- Add resource doc `resource_tc_dbdc_db_custom_disaster_recover_group.md` and
  unit tests `resource_tc_dbdc_db_custom_disaster_recover_group_test.go`
  (gomonkey mocks, per the new-resource convention).

## Capabilities

### New Capabilities
- `dbdc-db-custom-disaster-recover-group-resource`: Manages the full lifecycle
  (create / read / update / delete) of a DB Custom placement group
  (置放群组) through the `dbdc` service, including async task polling for create
  and delete operations.
